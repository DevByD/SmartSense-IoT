## Failure & Fault Tolerance Tests

### 1. Backend Failure (`API Offline`)
- **Test:** Backend process halted; clients attempt network requests.
- **Expected:** React website displays connection error state with "Retry" button. Expo mobile displays "Unable to connect to SmartSense API" with Retry button. Neither application crashes or throws uncaught exceptions.
- **Actual:** Both clients catch `NETWORK_ERROR` (status 0), render clean error views, and resume polling upon backend restart.
- **Result:** **PASS**

### 2. MQTT Broker Failure (`Broker Offline`)
- **Test:** MQTT broker unreachable at `mqtt://localhost:1883`.
- **Expected:** Simulator logs reconnection warnings and continues generating local telemetry without throwing unhandled exceptions. Node-RED receives no new messages. Previously stored database values remain unchanged and are not falsely tagged as fresh.
- **Actual:** Simulator catches socket errors gracefully and enters auto-reconnect backoff. Database retains existing data.
- **Result:** **PASS**

### 3. Node-RED Failure (`Engine Offline`)
- **Test:** Node-RED process terminated while simulator and backend run.
- **Expected:** MQTT broker receives telemetry from simulator. Database receives no new processed readings. Express API continues serving cached database values with static timestamps.
- **Actual:** Express API returns stored values with original timestamps; clients observe no timestamp advances. System resumes immediately upon Node-RED restart.
- **Result:** **PASS**

### 4. Simulator Failure (`No Telemetry`)
- **Test:** Telemetry generator stopped.
- **Expected:** No new telemetry packets published. Database `latest/` remains static. `lastSeen` timestamp stops updating. Backend reports hardware status accurately.
- **Actual:** Last known values are preserved without synthetic data fabrication.
- **Result:** **PASS**

## Performance & Concurrency Audit

- **Polling Overlap Prevention:**
  - Web: `useIotData.js` uses `isFetchingRef` guard.
  - Mobile: `useLatestSensors.js`, `useAlerts.js`, and `useDevice.js` use `isFetchingRef` guards.
  - If a network request takes longer than the polling interval, subsequent ticks are skipped until completion.
- **Timer Teardown:**
  - All `setInterval` handles are cleared in `useEffect` cleanup return functions.
  - No timer memory leaks detected across mount/unmount cycles.
- **Alert Debounce Cooldown:**
  - Node-RED enforces a 10,000ms cooldown window per alert type, preventing alert floods from high-frequency sensor readings.

## Summary of Defects Discovered & Resolved

1. **Defect:** Simulator telemetry generator occasionally omitted `processedAt` timestamp before database ingestion.  
   **Resolution:** Verified Node-RED normalizer attaches ISO `processedAt` timestamp before storing in Firebase Realtime Database.  
   **Retest:** Verified in Phase 10 test suite.

2. **Defect:** Mobile `DashboardScreen` and `LiveMonitoringScreen` SSR tests initially hit loading state prior to hook resolution.  
   **Resolution:** Provided optional preloaded telemetry props allowing immediate deterministic SSR rendering and snapshot testing while preserving live hook polling in production.  
   **Retest:** Passed with 0 errors.
